Reading guide

One graph, seven coordinated views

Classification is the fact boundary. Current, planned, inferred, proposed, and legacy are deliberately separate. Implementation, operation, and governance are independent lifecycle axes.

Complete text catalogue. Guide is the reading order, the work front, the sibling sets and every operational surface resolved from the tracked inventory. Files answers which component owns a path. Dependencies shows domains until you narrow the graph, then components in layered order, then the focused neighbourhood of a selected component. Search and filters apply across every view; press / to search and Esc to close a panel.

Ask the command line for what a page cannot hold: python scripts/project_map.py q <path, component, symbol or words> adds the tests, users, citations, issue records and clones of a file from a live index of the working tree, and class <path> lists every sibling to sweep before a fix is complete.

Local workspace

The Files view describes the built project inventory. A local snapshot observes this checkout, including ignored and untracked files, dependencies, links and VCS metadata. It does not read file contents.

For first use, run this command from the repository root. Run it again when you need a new observation.

python -B scripts/project_map.py workspace --write

Open latest local snapshot. The snapshot may not exist until you generate it. It describes the time and scope of that observation, not current presence or freshness.

Workspace snapshots stay outside the committed project map.
